## 本项目选择

使用 base 的 Python 创建 `.venv-run`，通过 `--system-site-packages` 复用现有依赖。不会向 base 或其他既有环境安装、升级或卸载软件。

```bash
/home/rwj/anaconda3/bin/python -m venv --system-site-packages .venv-run
.venv-run/bin/python main.py
```

初期计划使用 PySide6 / PyQtGraph / sounddevice / soundfile，但环境盘点后改用已有 PyQt5 / Matplotlib / QtMultimedia / scipy.io.wavfile。功能与界面布局维持设计目标。

之前尝试的 Python 3.8 项目 `.venv` 安装已中止；当前运行环境是 `.venv-run`，不要混用。

## 音频设备限制

沙箱内 Qt 音频输出列表为空，但桌面权限下能识别到输入和输出设备。默认 ALSA 输出在测试中无法打开；显式选择 `plughw:CARD=Generic,DEV=0` 后，真实设备通过全零静音的“播放 → 暂停 → 继续 → 自然结束”验证，1 秒数据完成，播放器无错误信号。驱动曾输出恢复型 underrun 日志；本测试不评估音质，真人语音仍需最终试听。

界面已经加入“输出设备”下拉框，可以选择声卡，不需要修改任何 Conda 环境。

## 第二阶段：输入设备查询

只读查询 Generic 输入 `plughw:CARD=Generic,DEV=0`：16 kHz、44.1 kHz、48 kHz 的单声道 PCM16 均报告支持。系统 `default` 对这些请求报告不支持，并输出 ALSA dsnoop 打开失败日志，因此界面需要显式输入设备选择。没有在自动验证中启动真实麦克风录音，采集内容和实际录音听感仍需用户操作验收。
