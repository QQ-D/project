# 第四阶段：声音增强 Implementation Plan

> 按 superpowers:executing-plans 在当前会话实施；沿用用户已确认的v2设计、继续完善及GitHub同步授权。

**Goal:** 完成峰值归一化、音量、人声清晰度、三段EQ及原声/去噪/增强三个有效阶段的对比和导出。

**Architecture:** 独立不可变EnhancementSettings与enhance_audio函数；增强控制器通过现有后台任务生成独立缓存。可从原声或有效去噪缓存开始；需要去噪而缓存缺失时同一后台任务先去噪后增强，成功且快照仍有效才一起采用。

**Tech Stack:** 既有NumPy/SciPy、PyQt5与Matplotlib，无新增环境依赖。

**Spec:** `design/界面设计说明.md` 4.2、4.3、4.4。用户当前要求优先完善去噪之外的功能。

## Global Constraints

- 启用增强默认关闭；“一键增强”自动打开。归一化选项默认打开（只在增强执行时生效），目标峰值0.95。
- 增益0–2×默认1；清晰度0–100默认0；三段EQ各−12至+12dB默认0。
- 清晰度按比例叠加低−3dB/中+4dB/高+2dB；手动EQ表示额外增益。低架300Hz、中峰1500Hz(Q=1)、高架3000Hz，频率分别不高于Fs的0.1/0.25/0.4；架式斜率S=1。
- 采用[W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)双二阶系数，SOS滤波；全中性且不归一化时精确旁路。
- 顺序：EQ/清晰度→可选归一化→用户增益→越界限幅并显示数量；保持长度、采样率及原声不变。静音不除零。
- “使用去噪结果”默认关闭；一键增强直接处理原声。开启后使用或生成去噪缓存；参考模式仍要求噪声确认。
- 修改增强参数/来源开关仅使增强失效；更换原声清空所有处理缓存；去噪变化只使依赖去噪的增强失效。
- 开始处理按当前增强开关与来源策略运行；重复增强不叠加上一次增强。运行期间互斥、失败保留有效数据、过期快照拒绝、关闭等待后台任务。
- 自动验证仅使用合成数据，不录制真实麦克风。用户提供的音频诊断材料留在已忽略的.runtime目录。

2. 低采样率及短音频的EQ有限稳定、长度不变；Task1覆盖。
3. 参数/源缓存依赖和三阶段试听/保存一致；Task2覆盖。
4. 同一任务先去噪再增强的原子采用、失败和过期快照；Task2覆盖。
5. 取消采集/错误导入不能破坏有效增强，关闭不能遗留任务；Task2覆盖。
