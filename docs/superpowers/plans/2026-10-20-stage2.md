# 第二阶段：录音与底噪采集 Implementation Plan

> 执行方式：按 superpowers:executing-plans 在当前会话自行实施。已有 v2 设计及阶段路线经用户确认；用户已授权继续完善。

**Goal:** 麦克风语音与底噪可独立采集，并可从现有原声确认选择纯噪声片段。

**Architecture:** 独立 AudioRecorder 控制 Qt 音频输入，定长内存设备限制采集量，停止后转换为 AudioClip。原声复用已有后台分析/播放/保存流程。底噪单独保存并显示来源、时长与确认状态；片段选择使用对话框波形、数值与试听。

**Tech Stack:** 继续复用 `.venv-run` 与已有 PyQt5 / QtMultimedia / NumPy / SciPy / Matplotlib，不安装新依赖。

**Spec:** `design/界面设计说明.md` 第 2、4.1、6 节；补充交互写在本计划中。

## Global Constraints

- 在 `feat/stage2-recording` 分支就地实现；复用本机环境，避免额外 worktree 复制环境。
- 第一阶段已有 37 项测试必须保持通过。
- 录音目标 44.1 kHz、单声道 PCM16，支持 16/44.1/48 kHz 目标选择；设备不支持时接受其近邻 PCM 格式，显示实际采样率。
- 语音最长 300 秒，环境底噪默认最多 1.5 秒；停止、取消、设备错误与关闭窗口均释放输入设备。
- 录音期间不能导入/导出、播放或并行采集；结束录音后后台分析，成功后才替换原声。
- 底噪与原声分别存储；底噪选择要求至少 0.1 秒，必须确认片段没有人声。
- 导入新文件或更换输入设备后，已有底噪标记待确认；明确确认沿用或重新采集才能作为有效参考。原声内选段随原声替换失效并清除。
- 本次不启用去噪与增强，不产生虚构处理结果。自动测试不采集真实麦克风。

## Review Focus

- 不完整 PCM 帧、多声道、设备实际采样率与期望不一致。
- 启动失败、录音中设备断开、短录音与取消均不能覆盖有效原声/底噪。
- 达到上限后的排队信号不得停止下一次采集。
- 导入/保存/播放、采集与后台分析互斥；关闭窗口不遗留设备与后台任务。
- 选段边界、最短时长、确认勾选、过期参考处理和取消对话框。
